# pkg_utility_hangglider

Based on my comprehensive audit of the utility_hangglider package, here are my findings:

## Findings

- `pxrt_e_classes.lua:168-180` - **high** - CWorm.Glider field does not exist in the runtime. The transpiled code at `paratest.lua:71` accesses `self.Owner.CurWeapon`, `paratest.lua:81` checks `self.Owner.ObjState`, and `paratest.lua:222` references `w.Glider.Deployed`, but the runtime provides no CWorm.Glider proxy field. PX scripts extend CWorm with a `Glider` member at construction (`paratest.pxc:309`), but pxrt has no mechanism to attach script-owned objects to engine worms. **Fix**: Add E.special.CWorm.Glider to return a per-worm glider state table, keyed by worm address.

- `pxrt_e_classes.lua:168-180` - **high** - CWorm.PhysicsData field missing. The PX source `utility_hangglider_render/paratest.pxc:159` reads `Owner->PhysicsData->SpX` to track velocity, but the runtime exposes no PhysicsData field on CWorm proxies. The transpiled code works around this by reading SpX/SpY directly from the worm (`paratest.lua:101-102`), but the original intent was a pointer indirection. **Fix**: Not needed if scripts only use SpX/SpY; document that PhysicsData is not exposed.

- `pxrt_e_funcs.lua:312-333` - **medium** - CSoundFile.Play signature mismatch. The transpiled code calls `mc(__G__.hangopen, "Play", self.vol, self.pan, 0)` (`paratest.lua:86`) with (volume, pan, priority), but the runtime's CSoundFile.Play at line 325 expects `(self, super, vol, pitch, prio)` where the second argument is pitch, not pan. PX's CSoundFile::Play took (volume, pan, looping) but the runtime maps it to the host's playSoundLocal(vol, pitch, source, id, prio). **Fix**: Change CSoundFile.Play to accept (vol, pan, loop) and ignore pan (or map pan to a source position if the host supports it).

- `pxrt_e_funcs.lua:119-125` - **low** - CalculateSoundVolume stub. The transpiled code calls `__G__.CalculateSoundVolume(self.Owner.PosX, self.Owner.PosY)` (`paratest.lua:84-85`) expecting distance-based attenuation, but the runtime's CalculateSoundVolume returns a constant 1.0. The hand-written port omits volume calculation entirely and plays at full volume. **Fix**: Implement distance-based volume using camera position if spatial audio matters.

- `pxrt_core.lua` - **high** - CWorm constructor override not invoked. The transpiled code registers `__P__:override("CWorm", "CWorm", ...)` to attach a Glider object at worm construction (`paratest.lua:192-197`), but pxrt provides no hook to run script constructors when the engine creates a CWorm. Engine worms are born in WA's memory; the runtime only proxies them on first access. **Fix**: Add a per-class onNewObject callback in pxrt_e_classes that fires when a proxy is first created for an engine object, allowing scripts to attach state.

- `px_pipeline/testout/lua/utility_hangglider/paratest.lua:213-259` - **high** - CDDQueue::AddSprite override will not be called. The transpiled code overrides CDDQueue::AddSprite to replace parachute sprites with rotated glider sprites (`paratest.lua:213`), but the runtime has no CDDQueue class and no hook for intercepting sprite draws. The hand-written port uses SetWeaponSpriteOverride (jelly API) instead (`main.lua:357-362`). **Fix**: Document that sprite overrides require the host's SetWeaponSpriteOverride; CDDQueue::AddSprite is unsupported.

- `px_pipeline/testout/lua/utility_hangglider/paratest.lua:224` - **medium** - CWorm.AddSpriteEx rotation argument ignored. The transpiled code calls `mc(w, "AddSpriteEx", 6, w.PosX, w.PosY, sprite, frame, rotation, scale)` to draw a rotated glider, but pxrt_e_classes.lua:73-74 implements AddSpriteEx as a call to E.drawSprite which checks for rotation support (`pxrt_e_classes.lua:53-59`) and falls back to unrotated if E.drawSpriteRot is unavailable. The hand-written port pre-rotates sprites into 58-angle sheets instead. **Fix**: None if E.drawSpriteRot exists; document that rotation requires host support or pre-rotated sprites.

- `pxrt_e_soft.lua:311` - **medium** - TraceMask function exists but signature differs. The transpiled code calls `__G__.TraceMask(self.Owner, self.Owner.ColMask, x1, y1, x2, y2, flags, &hitX, &hitY)` with 2 output refs (`paratest.lua:152`), but pxrt_e_soft.lua:344 defines `BF._TraceMask` (underscore prefix) with 6 output refs. The PX utils library wraps _TraceMask as TraceMask with the 2-ref signature, so this works if utils is loaded. **Fix**: Verify utils/utils_steps dependency is loaded before utility_hangglider runs.

- `px_pipeline/testout/lua/utility_hangglider/paratest.lua:27-30` - **low** - CSoundFile constructor uses GetAttachment for asset paths. The transpiled code calls `F.GetAttachment("hangopen.wav")` then passes the result to `CSoundFile`, but pxrt_e_funcs.lua:312-323 expects the CSoundFile constructor to receive a bare filename and calls `asset(file)` internally (line 317). If GetAttachment already resolves to a full path, calling asset() on it may double-resolve. The hand-written port calls registerCustomSound directly. **Fix**: Check if GetAttachment + asset() double-resolves; if so, skip GetAttachment or make CSoundFile accept both.

- `px_pipeline/testout/lua/utility_hangglider/paratest.lua:18-88,158-210` - **medium** - CWorm.Message override requires message hook. The transpiled code overrides CWorm::Message to intercept M_FRAME, M_PUP, M_PDOWN, M_PLEFT, M_PRIGHT (`paratest.lua:198-211`), but pxrt only hooks a few specific messages (RenderWorm, SetAnimEx per pxrt_e_hooks.lua:677-731). M_FRAME and input messages reach engine worms but bypass script overrides. The hand-written port hooks onFrame and onMessage callbacks from the jelly API. **Fix**: Add message dispatch hooks in pxrt_e_hooks for M_FRAME and input messages if scripts override CWorm::Message.

- `pxrt_e_hooks.lua:691-710` - **low** - CSpriteAnim::SetAnimEx hook exists but CWorm.Anim field missing. The transpiled code at `paratest.lua:260` overrides CSpriteAnim::SetAnimEx, and the runtime hooks it (pxrt_e_hooks.lua:691), but scripts access it via `w->Anim` (PX source line 398). The runtime provides no CWorm.Anim field to return the worm's CSpriteAnim proxy. **Fix**: Add E.special.CWorm.Anim to return a CSpriteAnim proxy for the worm's animation state (worm.__a + anim offset).

- `main.lua:357-362` vs `paratest.lua:213-259` - **high** - Rendering approach mismatch. The transpiled code uses CDDQueue::AddSprite overrides with rotation (PX approach), but the hand-written port uses SetWeaponSpriteOverride to replace specific sprite indices with pre-rotated sheets. The transpiled version cannot run on pxrt without CDDQueue hooks; the hand-written port is the only working implementation. **Fix**: Document that utility_hangglider requires the jelly-native port; pxrt cannot run the transpiled PX version.

- `main.lua:138-279` vs `paratest.lua:64-157` - **medium** - Physics calculation differences. The hand-written port directly writes worm velocity to memory (`main.lua:275-276: wr(worm + 0x90, g.SpX * FIX)`), while the transpiled version assigns to fields (`paratest.lua:155-156: self.Owner.SpX = self.ParaSpX`). Both work if pxrt proxies SpX/SpY as writable, but the hand-written port also detects wall collisions by comparing intended vs. actual position deltas (`main.lua:242-248`), which the PX version handles via TraceMask. The PX version's collision detection may fail if TraceMask is unavailable or misconfigured. **Fix**: Verify TraceMask works or port the collision detection from main.lua.

- `main.lua:188-198` vs `paratest.pxc:106-122` - **low** - Weapon detection logic simplified. The PX code checks 4 weapon names (Hang-Glider, Parachute, Hot Air Balloon, Umbrella) using CurWeapon->CheckName, but the hand-written port caches the glider weapon ID once and compares numerically. Both work, but the port is more efficient. Not a bug, just an optimization difference.

## Notes
