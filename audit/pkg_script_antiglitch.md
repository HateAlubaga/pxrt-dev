# pkg_script_antiglitch

## Findings

- `px_pipeline\testout\lua\script_antiglitch\AntiGlitch_SCRIPT.lua:19` - **high** - **K.Root.Timer is not readable** - The script reads `K.Root.Timer` and `K.Root.RetreatTimer` to detect standstills, but pxrt_e_consts.lua:62 shows `K.Root` is a dynamic proxy that returns a CTurnGame object. No `Timer` or `RetreatTimer` fields are defined for CTurnGame in pxrt_e_classes.lua. **Scenario:** Every frame the script compares timers; both reads return 0 (missing field fallback), so the equality always holds and AG_Standstill_Time increments every frame instead of only when timers are actually frozen. Anti-glitch triggers too early. **Fix:** Add `Timer` and `RetreatTimer` to the CTurnGame proxy in pxrt_e_game.lua or pxrt_e_classes.lua, reading from the correct memory offsets (or stub them if unavailable).

- `px_pipeline\testout\lua\script_antiglitch\AntiGlitch_SCRIPT.lua:211-212` - **high** - **K.Root.Timer and K.Root.RetreatTimer writes missing** - The script writes `self.AG_Turn_Time = K.Root.Timer` and `self.AG_Retreat_Time = K.Root.RetreatTimer` to capture timer snapshots, but these fields are not readable (see above). **Scenario:** Both capture 0 every time, so the script thinks the timers never advance and triggers anti-glitch immediately. **Fix:** Same as above.

- `px_pipeline\testout\lua\script_antiglitch\AntiGlitch_SCRIPT.lua:193-195` - **high** - **CTurnGame::FinishTurn is stubbed** - Stage Seven calls `mc(K.Root, "FinishTurn", 0/1/2)` three times, but pxrt_e_classes.lua:250 shows `CT.FinishTurn = function() once("finishturn", "pxrt: CTurnGame::FinishTurn unsupported") return 0 end`. **Scenario:** The script expects FinishTurn to skip the turn and reinstate the game, but it does nothing; the game remains stuck. **Fix:** Implement FinishTurn by sending M_SKIPTURN or calling the native WA function if available.

- `px_pipeline\testout\lua\script_antiglitch\AntiGlitch_SCRIPT.lua:101` - **med** - **GetWormHealth zero-check is wrong** - The script checks `if isnull(mc(K.GS.Info, "GetWormHealth", worm.WormTeam, worm.WormNumber))`, but pxrt_e_classes.lua:283-286 shows GetWormHealth returns an integer (0 if not found, health otherwise). `isnull()` on an integer is always false unless it's exactly 0. **Scenario:** The script tries to kill worms at 0 health, but the null-check fails; worms with 0 health are treated as null and skipped instead of being killed. **Fix:** Change to `if (mc(K.GS.Info, "GetWormHealth", worm.WormTeam, worm.WormNumber) == 0)`.

- `px_pipeline\testout\lua\script_antiglitch\AntiGlitch_SCRIPT.lua:64` - **low** - **Env.Objs iteration is 1-based** - The script loops `while (i < K.Env.Objs.Count)` starting from `i = 1`, but Lua arrays are 1-based and the loop uses `K.Env.Objs.Objs[ti(i)]`. pxrt_e_soft.lua:250-253 shows the Objs array is also 1-based (adjusted by `ti(i) + 1`). **Scenario:** The loop skips index 0 (which doesn't exist in Lua) and accesses indices 1..Count-1, missing the last object. For a Count of N, indices 1..N-1 are checked, so the Nth object is never processed. **Fix:** Change loop condition to `while (i <= K.Env.Objs.Count)` (but verify the transpiler's intent—PX may be 0-based).

- `px_pipeline\testout\lua\script_antiglitch\AntiGlitch_SCRIPT.lua:3` - **low** - **Transpiler emits file path in pxc format** - The transpiler writes `__P__:file("script_antiglitch/AntiGlitch_SCRIPT.pxc")` with forward slashes, but the PX source uses backslashes on Windows. **Scenario:** No runtime impact (just metadata), but inconsistent with platform conventions. **Fix:** None needed; this is cosmetic.
