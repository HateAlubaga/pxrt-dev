## Findings

- `px_pipeline/testout/lua/utility_personal_invisibility/personal_invis_script.lua:18` - high - `self.isInvisible` field not backed by runtime - The transpiled script sets `self.isInvisible = 0` or `1` on the worm object, but the runtime's CWorm field table (pxrt_engine.lua:202-212) does not define an `isInvisible` field. This field is neither a real WA memory offset nor a pseudo-field supported by the runtime, so writes go to a Lua table slot that WA never reads. The worm will never actually become invisible in-game. - Add `isInvisible` to FIELDS.CWorm with a suitable memory offset if WA 3.8.1 has such a field, or implement it as a script-only table in pxrt_e_classes.lua with custom rendering logic.

- `px_pipeline/testout/lua/utility_personal_invisibility/personal_invis_script.lua:16` - high - CheckName method not implemented for CWeapon - The script calls `mc(Weap, "CheckName", "Personal Invisibility")` but runtime provides CheckName only at pxrt_e_classes.lua:537 for weapon struct proxies (those with `__a` or `__id`), not for method-call dispatch through `mc()`. The `mc()` helper (pxrt_core.lua) expects the method to exist in the method chain. If Weap is a weapon proxy without the right metatable setup, CheckName won't be callable. - Verify that weapon proxies returned to FireFinal have CheckName accessible via `mc()`, or change transpiler to use `Weap:CheckName()` syntax instead of `mc()`.
