# CWeaponLaunch field map (WA 3.8.1, image base 0x400000)

Launch-relative offset L = entry offset - 0x3C. Machine-readable copy: `launch_fields.json`
(generated by `re_launch_gen.py`, shape `{name: {off, entryOff, kind, conf, note, extra?}}`).

## Method

1. Rebuilt the vanilla weapon table by simulating the straight-line init code at 0x537320-0x53ad7a
   (`re_launch_sim.py`: register tracking + `rep movsd` template copies, writes `re_launch_wtab.json`,
   2863 values, 29 unknown). `re_launch_show.py <ids> <lo> <hi>` prints a launch-relative view.
2. Located the consumers. The launch block is copied into the CTaskMissile at missile +0x15C
   (missile off = L + 0x15C). The ctor (0x507d10) copies 42 dwords into a working block ("DB") at
   missile +0x2D4: block A (L+0x0C..0xB3) when ShootDesc+0x20 == 0, otherwise block B (L+0xD0..0x177,
   a `rep movsd` copy of A patched by the init code, stride 0xC4). DB offset d maps to L = 0x0C + d (A)
   or L = 0xD0 + d (B). Fields L+0x00..0x0B and L+0xB4..0xCF are read straight from the launch copy.
3. `re_launch_uses.py` listed every `[reg+disp]` access to the DB range and to the launch copy inside
   0x507d10-0x50bfb0 (`re_launch_dbuses.txt`, `re_launch_lcuses.txt`); each consumer was disassembled
   (`re_dis.py`) in the ctor 0x507d10, init 0x5089d0, collide 0x508c90, render 0x5091a0,
   explode 0x509ac0, HandleMessage 0x50b400 (jump table 0x50bee4 / byte map 0x50bf08).
4. Named the offsets by matching three independent sources: (a) what the code does with the dword,
   (b) the vanilla value pattern across weapons, (c) PX mod scripts that restore "vanilla" values
   (`ResetClustletLaunch` in utils_red.pxc, `thePlaneWeap.pxc`, oil drums). Example: the PX clustlet reset
   (54, 131, 20, 100, 50, 100, 0, 100, 0, 10000, ...) equals vanilla block B of the Cluster Bomb field for
   field, which fixes the whole anim/speed/wind/gravity/time run at B+0x14..B+0x44.
5. All values are plain ints (percent or ms). Nothing in the launch block is 16.16 fixed; the code
   converts with `*0x51eb851f >> 5` (divide by 100) or `<<16` where needed.

### Evidence per field

- spriteSize L+0: 4th argument of `ConstructCGameTask` (collision mask / radius index) in the ctor; Bazooka and
  Grenade 2; PX clustlet reset sets 2.
- launchSpeed L+4: Mortar 100, Homing Pigeon 33, Sheep Launcher 50, everything else 0; PX clustlet reset sets 0.
  Fixed shot power percent (0 = use the player's charge).
- runAway L+8: missile +0x164 is tested/set in the frame handler near the 800 ms-before-blast worm shout;
  1 for Grenade, Cluster, Banana; PX clustlet reset `runAway = true`.
- explosion.flags L+0xC: DB+0; OR-ed into object flags, tested in collide (0x508cd9, 0x508d52). 137342
  Bazooka/clustlets (PX reset 137342), 0 Grenade.
- bias/pushPower/damage/dmgVar L+0x10/14/18/1C: DB+4/8/0xC/0x10, loaded together at 0x509ae8-0x509b12 and
  passed to CreateExplosion 0x548080 (dmgVar through 0x547cb0). Values 0/100/50/0 for the Bazooka match
  PX script defaults.
- unk L+0x20: `idiv [+0x2e8]` in the ctor, result added to the sprite index; clustlet block = 1, PX reset 1.
- anim.spriteIndex L+0x24 (+0x2EC): render + off-screen check; 54/51 clustlets match PX.
- anim.type L+0x28: switch at 0x5094ba, jump table 0x50968C = {0x5094CD, 0x50952C, 0x50950B, 0x509564};
  values 4/5/6 handled in the frame handler at 0x50b6aa (+= [obj+0x128]/100, /50, /25).
  Raw 0 timer progress; 1 spin ([obj+0x8C], [obj+0x98]); 2 follow travel direction; 3 pigeon-style
  horizontal-speed frame; 4 slow; 5 medium; 6 fast. Vanilla: Bazooka/Mortar/Sheep Launcher 2, Homing/Grenade/
  Cluster/Banana 1, Pigeon 3, sheep family 6. PX clustlet reset says WAT_Rotation and vanilla clustlet = 1,
  so WAT_Rotation = 1. Slow/Medium/Fast = 4/5/6 follows from the three increment rates. HSpeed = 3 follows from
  the |vx| dependence. TrackMovement = 2 follows from the atan2 frame. TrackSpeed = 0 only by elimination.
- anim.trailIndex/trailPower/trailSpeed L+0x2C/30/34 (+0x2F4/F8/FC): trail loop at 0x50ba79-0x50bb6b
  (sprite id, spawn accumulator, puff scale). Match PX reset 131/20/100.
- anim.unk L+0x38 (+0x300): in the underwater branch 0x50bb8a (Y >= water level) used as bubble spawn rate.
  PX scripts set 50 like vanilla.
- speedMultipler/windFactor/gravityFactor L+0x3C/40/48: ctor init at 0x50817c-0x5081a9 copies to CGObject
  +0x58 path / +0x5C WindFactor / +0x60 GravityFactor; wind 100 Bazooka, 0 Grenade and clustlets (PX reset 0).
- countdownFrom/timeBeforeExplosion L+0x4C/50: ctor 0x507f0a-0x507f1c, render 0x509269, anim.type 0 divisor.
  Grenade fuse 5000 / 0, Bazooka 0 / 9000. Units ms.
- sound.* L+0x54..0x60: ctor 0x508ab1 (looped sound), 0x507fb8 (delay counter), 0x50b868-0x50b8a8 (delayed
  explosion sound). Holy Hand Grenade 1 / 104 / 1800 confirms the three fields after soundIndex.
- explodeOnSpace L+0x64: see uncertainties.
- action L+0x68: switches at 0x508051 (ctor, jump table 0x508300), 0x508250 (flag table 0x508314),
  0x50b9ad (water, jump table 0x50bf88, 6 entries 0..5), 0x5093a3/0x509598 (render), 0x508f09, 0x50b60f.
- explodeInto L+0xB4: switch at 0x509b43, jump table 0x509B84 = {0x509B79, 0x509B4F, 0x509B6D, 0x509B4F}.

## Full launch map (A block, L = 0x0C + DB offset; block B = A + 0xC4)

```
L+0x00 spriteSize          L+0x04 launchSpeed         L+0x08 runAway
L+0x0C explosion.flags     L+0x10 explosion.bias      L+0x14 explosion.pushPower
L+0x18 explosion.damage    L+0x1C explosion.dmgVar    L+0x20 unk
L+0x24 anim.spriteIndex    L+0x28 anim.type           L+0x2C anim.trailIndex
L+0x30 anim.trailPower     L+0x34 anim.trailSpeed     L+0x38 anim.unk
L+0x3C speedMultipler      L+0x40 windFactor          L+0x44 movementRandomness (med; jitter in frame handler)
L+0x48 gravityFactor       L+0x4C countdownFrom       L+0x50 timeBeforeExplosion
L+0x54 sound.soundIndex    L+0x58 sound.useExpSound   L+0x5C sound.expSoundIndex
L+0x60 sound.expSoundDelay L+0x64 explodeOnSpace      L+0x68 action
L+0x6C collisionFlags (OR-ed into CGObject +0x34)     L+0x70 bounce % (action 2/5; 0 = player setting)
L+0x74 friction % (x game friction setting)
L+0x78..0xB3 per-action union, not named: sprite-cycle ids for action 4 (L+0x78..0x84), explosion/jump/walk
        parameters for the sheep family (L+0x88..0xA0, consumers 0x508dbc..0x508f09 and 0x50a7e0..0x50ac44),
        L+0xA4 = control/fly capability flag tested with action 3 at 0x50b511 and 0x50b8c4 (med-low).
L+0xB4 explodeInto         L+0xB8 launch sound (one-shot at creation, med; candidate for 'wav')
L+0xBC childCount          L+0xC0 childSpeed (low)    L+0xC4 childSpeedVar (low)
L+0xC8 unknown (-1 on Mortar, 0 elsewhere)            L+0xCC childSpread degrees (low)
L+0xD0..0x177 block B: same layout as L+0x0C..0xB3 shifted by +0xC4 (clustlets/second stage; used when
        the missile is spawned with ShootDesc+0x20 != 0). Fields before +0x0C and after +0xB3 are NOT duplicated.
```

For gun / flamer / bow weapons (entry +0x30 type 1/2/4) the same bytes hold different data (shot count,
spread, delay, ...). The 0x178 block is a union; this map applies to missile-class entries (type 3). Shot count,
spread and delay for non-missile types were not mapped. For missiles the clustlet "shot count" is L+0xBC and
spread is L+0xCC.

## Uncertainties and things to treat as unverified

- anim.type names: values 1..6 are solid; TrackSpeed = 0 is a guess by elimination, and HSpeed = 3 is
  medium confidence. The existing `pxrt_e_consts.lua` WAT values (0..6 in wiki-ish order) disagree with the
  code and should be replaced: Rotation 1, TrackMovement 2, HSpeed 3, Slow 4, Medium 5, Fast 6, TrackSpeed 0(?).
- action: offset certain, enum names not recoverable from the exe. Raw values 0..5 as described. The PX names
  (None, Bounce, Homing, Dig, Roam) only have five entries for six raw values. Best guess None 0, Homing 1,
  Bounce 2, Roam 3, Dig 4 (Roam=3 med because `ActionType = 3` picks crates and the walker turns at walls;
  Dig = 4 low because no vanilla weapon uses 4). Vanilla Sheep Launcher uses 5 which has no PX name here.
  The existing consts (Bounce 1, Homing 2, Dig 3) are probably wrong. The PX clustlet/airplane scripts
  use `WAction_None` for plain explode-on-impact missiles, which fits None = 0 (no special handling).
- explodeOnSpace: offset L+0x64 comes from the fire-again message handler and from the vanilla pattern (set on
  the sheep family and Sheep Launcher, never on rocket types); PX scripts treat it as bool (Chilli Bomb, Homing
  Digger set true). I did not trace which worm key sends message 0x2c, so the "on Space/Enter" reading is by name.
  A value of 2 has a distinct code path (re-arm) that is never set in vanilla.
- useExpSound: behaviour of the "only while not moving" gate is read from the code; semantics beyond Holy Hand
  Grenade are untested.
- wav: not found. No corpus script touches a launch `wav`, and no other launch dword has a sound-like use.
  The only candidate is L+0xB8 (one-shot creation sound, Pigeon 51, Sheep Launcher 50). Treat as unresolved.
- unk (L+0x20) and anim.unk (L+0x38): roles derived from code; names kept as in PX.
- The init simulator ignores game-version branches (assumes latest) and has 29 unknown stores; entries beyond
  index ~21 in the helper name list `re_launch_show.py` are unreliable, so per-weapon claims above use
  the code-derived type/subtype rather than those names.
- Child/cluster parameters L+0xC0, 0xC4, 0xC8, 0xCC and the per-action union L+0x78..0x94 are only
  partially decoded.
